9.2 Les pointeurs

Définition simple

Les pointeurs sont des variables qui mémorisent les adresses de la mémoire.

Ils donnent accès à un emplacement de la mémoire interne de l’ordinateur

Une variable permet d'accéder à un emplacement mémoire

Un pointeur permet d’accéder à n’importe quel emplacement mémoire

9.2 Les pointeurs

Définition


a)  Un pointeur est une variable

b)  Un pointeur est une variable qui contient une adresse

c)  Un pointeur peut contenir l’adresse d’une autre variable


Si un pointeur P contient l'adresse d'une variable A, on dit que «P pointe sur A»

9.2 Remarques

Les pointeurs et les noms de variables donnent accès à un emplacement de la mémoire. Mais :

9.2 Exemples



              ptrX = &x;

Si un pointeur ptrX pointe sur une variable x alors *ptrX peut être utilisé partout où on peut écrire x

Les expressions suivantes sont donc équivalentes

y = *ptrX+1≡y = x+1
*ptrX = *ptrX+10≡x = x+10
*ptrX += 2≡x += 2
++*ptrX≡++x
(*ptrX)++≡x++

⚠ Sans les parenthèses : *ptrX++ ≡ *(ptrX++), c'est le pointeur qui est incrémenté, pas x

➔ ptrX ne pointe plus sur x : lire *ptrX ensuite est un comportement indéfini

Dans le dernier cas, les parenthèses sont nécessaires :
Le ++ postfixé est prioritaire sur l'opérateur * (voir le tableau de la slide précédente) : sans les parenthèses, c'est le pointeur ptrX qui serait incrémenté, et non pas l'objet sur lequel ptrX pointe.

9.2 Pointeurs particuliers



            int *ptrP = NULL;

La constante NULL est utilisée pour indiquer que ptrP ne contient pas encore d'adresse valide.

Déréférencer NULL : comportement indéfini, en pratique un plantage immédiat → l'erreur se voit tout de suite

Bonne pratique : initialiser tous les pointeurs à NULL

C23 : nullptr joue le même rôle ; le cours garde NULL, présent dans tout le code existant et les bibliothèques


Le type void* est utilisé quand on ne sait pas encore le type sur lequel va pointer le pointeur → type retourné par malloc (chapitre 10)

void *ptrP;

Déréférencer NULL est un comportement indéfini ; sur un PC, le système arrête le programme (segmentation fault). C'est la raison de la bonne pratique : un pointeur non initialisé écrit à un endroit quelconque, parfois sans rien de visible, alors qu'avec NULL l'erreur se voit à coup sûr et tout de suite. On peut aussi tester un pointeur avant de s'en servir : if (ptrP != NULL).

C23 ajoute le mot-clé nullptr (int *ptrP = nullptr; compile avec la commande du cours). Le cours garde NULL : c'est ce qu'on trouve dans le code existant, les bibliothèques et la documentation.

Attention, un pointeur void * ne peut pas être déréférencé sans un casting sur le type souhaité !
void *ptr;
int a = *ptr; // Erreur de compilation
int a = *(int*)ptr; // Est possible

9.2 Vue d’ensemble



              int a = 6;

Constante

6 est une constante qui est déterminée lors de la compilation ; elle n’est pas modifiable par le programme



              int a;
              a = 6;

Variable

L’adresse de a ne change pas pendant sa durée de vie. Le contenu de a, sa valeur, est modifiable par le programme



              int *ptr = NULL;
              ptr = &a;

Pointeur

L’adresse de ptr ne change pas pendant sa durée de vie ; le contenu de ptr, l’adresse de la variable a, est modifiable par le programme

9.3 Passage de paramètres

En programmation, il existe 2 modes de passage de paramètres

Passage par valeur

en entrée : le compilateur passe la valeur à la fonction

Passage par adresse

en entrée/sortie : le compilateur passe l’adresse de la variable

→ la fonction peut lire et modifier la valeur de la variable


En C, le passage de paramètres ne se fait que par valeur !

la fonction appelante fait une copie des valeurs passées en paramètre dans la pile d'exécution et la fonction appelée utilisera ces copies pour ses paramètres. Ces copies disparaîtront lors du retour à la fonction appelante. Donc toute modification de ces copies dans la fonction appelée n'a aucun effet sur les valeurs des variables de la fonction appelante.

9.3 Passage de paramètres


Principe


1.  La fonction appelante fait une copie des valeurs passées en paramètre dans la pile («stack»)

2.  La fonction appelée utilisera ces copies comme paramètres

3.  Ces copies disparaîtront lors du retour à la fonction appelante

⚠ 9.3 Pièges des pointeurs



              int* a, b;

Déclaration multiple : seul a est un pointeur, b est un int

➔ une * par pointeur : int *a, *b;



              int *p;
              *p = 20;

Pointeur non initialisé : adresse indéterminée

➔ comportement indéfini (gcc : -Wuninitialized)

➔ toujours initialiser : int *p = &x; ou NULL



              int *f(void)
              {
                int x = 1;
                return &x;
              }

Pointeur pendant : x disparaît de la pile au retour de f

➔ l’adresse renvoyée ne désigne plus rien

➔ comportement indéfini (gcc : -Wreturn-local-addr)

Déclaration multiple : l'étoile appartient au nom, pas au type. D'où l'écriture « int *a » du cours plutôt que « int* a ». gcc ne dit rien.

Pointeur non initialisé : comme toute variable locale, p contient ce qui traînait en mémoire. L'écriture se fait à un endroit quelconque : plantage, ou pire, rien de visible. Avec NULL, le déréférencement plante aussi, mais à coup sûr et tout de suite.

Pointeur pendant : même mécanisme que les copies de 9.3, les variables locales disparaissent au retour de la fonction. Avec gcc 15.2, f() renvoie même un pointeur nul. Le chapitre 11 (11.4, types de retour) y revient avec une chaîne.

Avec -Werror, les deux derniers pièges ne compilent pas (vérifié avec gcc 15.2).

9.4 Différence entre tableau et pointeur

int t[10];   // sizeof(t) → 40

Un tableau est une zone mémoire (ici 10 int de 4 octets).

Aucun pointeur n'est stocké : son nom est converti en l'adresse du premier élément.


int *ptr = t;   // sizeof(ptr) → 8

Un pointeur est une variable qui contient une adresse (8 octets).


⚠ Un tableau passé en paramètre à une fonction est converti en pointeur
(chapitre 8 : « dégénéré en pointeur ») :

void f(int tab[])   // sizeof(tab) → 8

sizeof(ptr) vaut 8 sur une machine 64 bits (hypothèse du cours), 4 sur une machine 32 bits.
Dans f, tab est un int * : sizeof(tab) ne donne plus la taille du tableau, il faut passer la taille en paramètre.

              const char *p = "abc";
              *p = 'X';
              p++;

Pointeur sur des char non modifiables

➔ modifier *p : erreur de compilation

➔ modifier p : permis, p reste une variable

Chaîne littérale (chapitre 8) : à ne pas modifier ➔ const

                            const char *ptrCh2)

Contrat : la fonction ne modifie pas la chaîne source

➔ vérifié par le compilateur

➔ accepte une chaîne littérale : mystrcpy(s, "abc");

🌶️ const après l’* : c’est q qui n’est pas modifiable

➔ *q = 'X'; permis, q++ interdit

Lecture de droite à gauche : « p est un pointeur sur des char const ». Le const protège ce qui est pointé, pas le pointeur.
gcc 15.2 : error: assignment of read-only location '*p'.

Chapitre 8 : char greeting[6] = "salut"; copie la chaîne dans un tableau, modifiable. Avec un pointeur, on pointe sur la chaîne littérale elle-même : la modifier est un comportement indéfini, d'où const char *. Même mot-clé que le tableau de valeurs constantes de 8.1.

Contrat : l'appelant sait que sa chaîne ne sera pas touchée ; la destination, elle, n'est pas const puisqu'on y écrit. C'est le prototype du vrai strcpy().

🌶️ char *const q : gcc 15.2 : error: increment of read-only variable 'q'. Les deux se combinent : const char *const.

            void mystrcpy(char *ptrCh1,
                          const char *ptrCh2)
            {
                while ((*ptrCh1++ = *ptrCh2++) != '\0')
                    ;
            }

Forme courte while (*ptrCh1++ = *ptrCh2++); : avertissement de gcc (-Wparentheses)

➔ un = dans une condition ressemble à une faute de frappe pour ==

Ordre : copie du caractère, avance des deux pointeurs (post-incrément), puis comparaison du caractère copié à '\0' : le '\0' final est copié avant l'arrêt. Le corps de la boucle est vide (le ; seul).
gcc 15.2, forme courte : warning: suggest parentheses around assignment used as truth value [-Wparentheses], en erreur avec -Werror (commande de la page).
Les doubles parenthèses while ((*ptrCh1++ = *ptrCh2++)); font aussi taire gcc, mais la comparaison explicite se lit mieux. Même forme que l'exemple 09.05.
